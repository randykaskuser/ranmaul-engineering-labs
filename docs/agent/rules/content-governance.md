# Content governance (Workspace Rules)

This repo is a technical platform. These are enforceable quality constraints.

## Platform content philosophy

Focus on:

- engineering thinking
- experiments
- troubleshooting
- systems
- practical documentation

Not:

- motivational writing
- generic tech news
- personal diary content

## Featured content rubric (locked)

Only feature content with strong technical value.

Minimum 3/4:

1. Real technical problem/context
2. Documented reasoning and constraints
3. Reproducible method or actionable framework
4. Practical takeaway applicable by technical readers

## Evergreen priority (locked)

Prefer evergreen:

- troubleshooting
- comparisons
- workflows
- experiments
- technical reasoning
- system design decisions

Avoid:

- trend-chasing
- short-lived announcements
- news-style posting

## Writing quality (locked)

Avoid:

- generic AI-style filler
- exaggerated marketing language
- shallow summaries
- keyword stuffing

Prioritize:

- concrete reasoning
- technical clarity
- evidence-backed statements
- practical usefulness

## Media governance (locked)

Cover policy:

- Preferred ratio: **16:9**
- Optional alternate: **4:3** (only when editorially necessary)

Rules:

- One clear cover per article.
- Prefer compressed media and meaningful captions.
- Avoid decorative overload.

## Code blocks (locked)

For QA-heavy technical content:

- Default: no forced line-wrap.
- Horizontal overflow allowed.
- Mobile must support smooth horizontal scrolling.

## Internal linking (pre-MDX rule)

- Prefer contextual links to related experiments/case notes.
- Link by conceptual relevance, not only within same domain.
- EN ↔ ID equivalents should cross-link where available.
- Avoid orphan articles (every published piece should link to or from at least one relevant entry).
